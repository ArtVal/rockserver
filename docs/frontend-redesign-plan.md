Статус: план, 2026-10-02. Этапы 2–5 реализованы локально по мокапам и не развернуты на публичный сайт. Локальная правка QR-привязки (повторный passkey не нужен при действующей сессии) вошла в переделанный экран этапа 5.

Мокапы показывают композицию и визуальное направление. Названия станций, треки, число избранных, время и аккаунт в них — демонстрационные. Интерактивные кнопки имитируют поведение и не обращаются к API. Реальная реализация должна брать данные из существующего состояния и сохранять действующие пользовательские сценарии.

Охват: каталог, поиск и фильтры, сетка/таблица, избранное, история, раздел устройств и Яндекс Дом, постоянный веб-плеер, отдельная страница QR-привязки, вход/регистрация в её контексте. Административная панель `/admin` не входит в эту переделку.

## Целевое поведение

1. **Навигация.** Основные разделы — «Эфир», «Избранное», «История», «Устройства». На широком экране — компактная боковая навигация, на телефоне — нижняя. У каждого раздела один явный заголовок. Фильтры жанров относятся к каталогу, а не к общей навигации. Счётчик избранного совпадает с фактическим списком после синхронизации.
2. **Каталог.** По умолчанию показывать таблицу, сохраняя переключение на сетку. Один поиск и один набор фильтров. На телефоне станции появляются без большого блока служебной информации над ними. Карточка и строка таблицы показывают название, логотип/заглушку, доступные метаданные, действие «Слушать» и избранное. Пустые значения не заменяются выдуманными треками, битрейтом или статусом.
3. **Плеер.** Один аудиоэлемент живёт на уровне кабинета и не пересоздаётся при переходе между разделами. На desktop видны станция, трек или понятный запасной текст, состояние потока, воспроизведение, переход между станциями, громкость и избранное. На телефоне в закреплённом блоке остаются название станции, трек/состояние и крупная кнопка паузы; блок не перекрывает список и нижнюю навигацию. При загрузке, паузе, ошибке потока и повторной попытке статус понятен. Переключение раздела не останавливает звук.
4. **Устройства и QR-привязка.** Раздел устройств показывает имя, тип, статус, дату и доступные действия без дублирования общего каталога. В этом же разделе сохраняется Яндекс Дом: подключение аккаунта Яндекса, показания датчиков с комнатой, единицами и временем обновления, обновление и отключение с подтверждением. Показать отсутствие подключения/датчиков, загрузку, ошибку и истёкший доступ. Ссылка из QR открывает отдельный мобильный сценарий с именем устройства, проверочной фразой, коротким кодом и сроком действия. При действующей браузерной сессии сразу доступно явное подтверждение; без сессии — вход/регистрация с возвратом к тому же запросу. Показать ожидание, успех, истёкшую/уже использованную ссылку и ошибку сервера. Подтверждение всегда остаётся явным; секрет ссылки не выводится на экран и не теряется при перерисовке.
5. **Язык и доступность.** Короткие русские названия вместо внутренней терминологии (`TUNER SELECTOR`, `Cloud Sync (LWW)` и т. п.). Видимый фокус, подписи кнопок для экранного диктора, доступные статусы через `aria-live`/`role`, достаточный контраст и удобные области нажатия. Не выводить ложные статусы вроде статического «ONLINE».

8. **Сделать таблицу видом по умолчанию и добавить бесконечную прокрутку списков (P0, новый этап).** При открытии кабинета использовать таблицу вместо сетки; переключатель сетка/таблица сохранить. Подгрузка следующих порций должна работать в обоих видах. В каталоге и поисковой выдаче загружать следующие страницы при приближении к концу списка через существующий `api.searchStations(query, limit, offset)` и серверные `has_more`/`total`. Использовать один запрос подгрузки одновременно, объединять страницы без повторов по ID; следующий offset считать по полученной серверной странице, а не по числу элементов после удаления дублей. При смене запроса/жанра сбрасывать страницы и исключать применение поздних ответов старого запроса. Сохранять уже показанные станции и позицию прокрутки при подгрузке и смене сетки/таблицы. Показать нижний индикатор загрузки, повтор ошибки следующей страницы и конец списка; оставить доступную кнопку «Загрузить ещё» как ручной вариант. Пустая страница не должна вызывать бесконечную серию запросов. Избранное и историю показывать последовательно порциями из уже синхронизированных данных, сохраняя общий счётчик, порядок и доступ ко всем записям; не запрашивать для них страницы общего каталога. Сначала проверить реальные ограничения `usePersonalSync` и не считать поэтапное отображение исправлением возможного ограничения синхронизации. Сопоставить UX с RockMobile, учитывая, что его каталог также использует локальные данные/курсорное обновление, а веб-поиск — offset. Серверный поиск сейчас ограничивает offset величиной 10000; явно обработать эту границу, а необходимость полного обхода большего каталога решать через существующий курсорный API каталога, не снимая ограничение молча. **Готово, когда:** в обоих представлениях на desktop и телефоне видны результаты дальше первой порции, нет пропусков/дублей и параллельных одинаковых запросов, смена фильтра не смешивает выдачи, повтор ошибки не стирает список; плеер продолжает работать. *Статус, 2026-10-02: реализовано локально. Поздние ответы старой выдачи отбрасываются счётчиком поколений; ошибка следующей страницы не стирает список и повторяется одной кнопкой; позиции прокрутки и загруженные данные сохраняются (в т. ч. при смене вида и разделе «Устройства»); выполненные выдачи кэшируются по запросу. Ограничения синхронизации проверены и не менялись: сервер отдаёт снапшот целиком (до 500 записей на коллекцию), браузер хранит 50 локальных записей истории — поэтапный показ не скрывает потерю. Проверено локальным harness на 390/800/1440 px (26/26 веб-тестов, включая исполнение реальной логики слияния страниц; обязательные проверки проекта пройдены); изменения не развёрнуты на публичный сайт.*
9. **Добавить голосовой поиск станций (P0, новый этап).** Рядом с существующим единственным поиском добавить кнопку микрофона. После явного нажатия запросить доступ, показать запись с автоматическим завершением после паузы и отменой повторным нажатием на микрофон, обработку, распознанный текст и результаты. По умолчанию голосовой поиск показывает результаты без автоматического запуска станции; пользователь выбирает её как при текстовом поиске. Сначала сверить `RockserverVoiceClient`/голосовой сценарий RockMobile и контракт `/api/v1/voice/stream`, затем проверить пригодность для браузера: существующий маршрут принимает PCM s16le mono 16000 Hz, а при отсутствии Authorization использует анонимные лимиты; действующая browser-cookie не означает native-авторизацию.
